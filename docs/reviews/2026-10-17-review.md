# Talon review, 2026-10-17 (master 55b63366, 1.8.30-rc10)

Six read-only reviewers covered this week's diff (501a278e..55b63366), chat core and sync, calls, the ship-app clients, the UI across both shells, and the platform leaves. Nothing was built or run by them. Every High below was checked against the code by the lead session. Mediums and Lows are the reviewers' findings, spot-checked where marked. Known held items R2, R3, R4, R6, R7 and R10 from the 2026-10-14 review were not re-reported. `compileKotlinIosArm64` was run on the rc10 tree (d0df2044): it compiles clean.

Paths are under `composeApp/src/` unless they start with `core/`, `iosApp/` or `.github/`.

## High (all verified in code)

- **H1. Android: a ring on a locked or dark screen answers itself.** `androidMain/.../Notifications.kt:324-372`. The full-screen intent, the content intent and the Answer action are one PendingIntent carrying `EXTRA_ANSWER_FROM`. Android launches the full-screen intent by itself over a locked screen, `MainActivity.consumeIntent` sets `pendingAnswerFrom`, and `TalonApp.kt:307-322` accepts the call. The phone in a pocket goes live with the mic on. Tapping the heads-up body also answers instead of showing the ring. Found by two reviewers independently. Fix: a separate PendingIntent (own request code, an `EXTRA_RINGING_FROM`) for the full-screen and content intents; only Answer carries the answer extras. Needs one device check (screen off, ring it).
- **H2. Android never fills the Activity feed's notices.** Only `commonMain/.../compose/App.kt:1198` builds a `NoticeRepo`, and only App.kt records notices (orrery proposals, loop results, Armillary payments, DM requests, group invites) and collects `OpenNoticeRequests` (:516). TalonApp shows the notices list and its badge (`TalonApp.kt:1744`) but nothing writes to it, and its `ArmillaryRepo` has no `noticeRepo` or notifier. Fix: build a NoticeRepo in TalonApp, pass it to ArmillaryRepo, record at the same sites, collect OpenNoticeRequests.
- **H3. Editing a task moves its due day a day earlier west of UTC.** `commonMain/.../calendar/CalendarEdit.kt:453` reads a task row's `l` in the calendar's zone, but the feed gives a task's due day at UTC midnight (`all: true`, as commit 89fa4bc9 says and the test fixtures show). In America/New_York a task due 1 Oct opens as due 30 Sep, and saving even a rename writes 30 Sep. `dueLabel` (`CalendarScreen.kt:1316`) has the same reading. Tests hide it (CalendarEditTest builds the row at New York midnight; CalendarScreenTest runs in UTC). Fix: read a task row's `l` as UTC in `taskDraft` and `dueLabel`, and make the task list's synthetic row a UTC midnight.
- **H4. iOS: the caller's call ends whenever its network interfaces change.** `core/.../call/CallController.kt:284, 1898-1912`; `CallEngine.kt:61` defaults `restartIce()` to null and neither `IosCallEngine.kt` nor `TalonRtc.swift` overrides it. `CallPush.swift:68-70` reports every interface change, so a calling iPhone that loses cellular in an elevator ends a working call with "connection failed". Fix now: on a null restart offer from a network change, leave the call to `MediaState.Failed`. Real fix: implement `restartIce` in TalonRtc.
- **H5. Android: the drawer cannot leave a group page.** `androidMain/.../ui/TalonApp.kt:762-775`. `closeSections()` clears sections, admin and group-info state and the chat, but not `openGroupFlag`, and the group page renders above apps, settings, assistant, loops and the chat list (`:2220`). From a group page, picking Chats, Settings or Assistant in the drawer does nothing; Calendar opens but the first Back closes the hidden group page. Desktop has the same gap in Escape (`App.kt:1952`) and the rail's `closeAll` (`App.kt:3291`). Fix: clear `openGroupFlag` in `closeSections`, and the group home and admin flags on desktop; better, make them `sections.flag()` pages.
- **H6. Desktop and iOS: a chat opened from outside the Chats tab stays hidden.** `commonMain/.../compose/App.kt:444-455`. `jumpToChat` sets `openChat` but cannot switch the rail tab (`uiSettings` lives inside the per-ship key block), and Home, Mail and Calendar take the whole content area. A chat notification tapped on iPhone while Talon was left on Home lands on Home; the call strip's Message does nothing on desktop; the next Back closes the invisible chat. Some callers work around it with `setActiveRailTab(Chats)`. Fix: have `jumpToChat` raise a request that a LaunchedEffect inside the key block turns into the tab switch.
- **H7. Settings changes made before the ship connects, or while it is unreachable, are wiped.** `commonMain/.../urbit/SettingsSyncImpl.kt:1707-1721` returns when `channel` is null (it is attached only after the bootstrap, `TlonChatRepo.kt:785`) and only logs a failed poke. The next full bootstrap applies each bucket ship-wins through `replaceAll`, deleting the unsynced local change. Folders, folder members, bookmarks, notify levels, rail items and group orders made in the first seconds after launch or with the ship down vanish at the next bootstrap. Same root: folder ids are per-device autoincrement but are the shared sync key, so two devices that each add a folder overwrite each other's name. Fix: queue settings writes with a sent mark per row and let bootstrap merge unsent local rows; globally unique folder keys.
- **H8. Pokes made before the event stream is collected each wait 15 s and lose the ship's answer.** `commonMain/.../urbit/UrbitChannel.kt:226-234, 347-353`: acks settle only in the `events()` forwarder, first collected at `TlonChatRepo.kt:830`, after the bootstrap. Pokes awaited inside it (level reconcile, settings seeding, the drain launched at :749) time out and are treated as success. On a first login this is minutes with no live stream, and a refused queued DM can be marked sent. Fix: start the events collector right after `subscribeAll`, before bootstrap work. (The reviewer also flagged, unverified, whether facts queued before the GET count toward eyre's clog limit.)
- **H9. Orrery's "Turn off" can leave the ship reading chats and mail, and say nothing.** `commonMain/.../orrery/OrreryRepo.kt:696-712`. Each reader is turned off only if its current state could be read; a failed read leaves it null and skips it without adding to `missed`, and with availability UNKNOWN the whole block is skipped. The page says Orrery is off. Fix: send each reader's "off" write when its state is unknown (they are partial merges), or add it to `missed`.
- **H10. A failed first Orrery check leaves Orrery half-working all session.** `OrreryRepo.kt:405-423, 789-802`. The beacon and actions refresh start only in `attach` when the first probe says PRESENT. A probe that fails (app started before wifi, a 502 during a restart) sets UNKNOWN; later probes from settings can set PRESENT but nothing starts the beacon. AI settings show "Checking your ship for Orrery." with the error hidden. Armillary has the same shape (`ArmillaryRepo.kt:200`, `AiSettingsSection.kt:448`). Fix: retry the probe with backoff, start the beacon whenever availability becomes PRESENT, show the error.
- **H11. Mail's poll reads only the open folder, so new-mail notices and the Mail pip stop after one search or folder switch.** `commonMain/.../mail/MailRepo.kt:166, 391-392, 997-1006`. The poll refreshes `pageKey()`, the current view; `announce` returns unless that is the inbox with no query, and `inboxUnread` reads a cached inbox page nothing refreshes. A search sets the view to All mail. Fix: when the open page is not the inbox, have the poll read the inbox page too and announce from it.
- **H12. Closing the mail composer with the ship down loses what was typed, and says it was kept.** `MailRepo.kt:970-976`, `commonMain/.../ui/screens/MailComposer.kt:234-239`. `keepDraft` failing says "what was written is still here until Talon closes", but the draft is in neither Drafts nor `_unsent`. Fix: on a failed save, add the draft to `_unsent` so the list offers Open.
- **H13. A note save that fails is always called a conflict, and with the ship down the unsaved body shows as saved.** `commonMain/.../ui/screens/NoteScreen.kt:165-167` (`if (ok) editing = false else conflict = true`), `commonMain/.../urbit/NotesRepo.kt:324-375`: the local edit is applied to the cache before the PUT, and a failed refresh returns early, so the cache keeps the edit as the current revision. A pending cross-ship write and "not an editor" also say conflict. Fix: return a reason from `updateNote` as `write()` does; on no answer, restore the host copy or keep the row marked unsaved.

## Medium-high (verified in code)

- **M1. Refreshing a channel deletes our failed and pending posts.** `commonMain/.../data/MessageDao.kt:222` `purgeStaleLocalIds` keeps only `queued`. A refused "Not sent" post vanishes on the next refresh; a pending post deleted mid-send then has nothing for `setStatus("queued"/"failed")` to mark, so it is neither shown, queued nor sent. Fix: delete only `status IS NULL`.
- **M2. The echo-reap fallback can delete a queued or failed post.** `TlonChatRepo.kt:4035-4036`, `MessageDao.kt:300-308` `reapOldestLocalTwin` has no status, parent or time filter. A re-send from another device reaps this device's queued copy, which is then never sent. Fix: restrict to `status = 'pending'` and `sentMs <=` the echo, matching parent.
